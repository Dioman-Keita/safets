# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SafeTS is a read-only static analysis CLI (`safets`) that uses the TypeScript Compiler API to find runtime crash patterns TypeScript's own checker allows (e.g. `Cannot read properties of undefined`). It **never modifies source** — `fix` only prints suggestions. Published to npm as `@safets-org/cli`; the binary is `safets`. Also ships as a composite GitHub Action (`action.yml`).

## Build & test workflow

The test scripts import from `dist/`, so **you must build before testing**:

```bash
npm run build        # tsc -p tsconfig.build.json -> dist/
npm run typecheck    # tsc --noEmit (the only "lint" — there is no ESLint/Prettier)
npm test             # runs the 6 suites below in order (build first!)
npm run ci:check     # typecheck + test + pack:check (closest mirror of CI)
```

There is no test framework — each suite is a standalone Node script under `scripts/` that asserts against fixtures. Run one suite directly while iterating:

```bash
npm run build && node scripts/test-detectors.mjs    # detector fixtures in cases/detectors-project
npm run test:cli          # CLI contract (flags, help, exit codes) — cases/cli-project
npm run test:integration  # end-to-end CLI runs
npm run test:json         # JSON reporter schema
npm run test:action       # GitHub Action shell wrapper
npm run test:smoke        # node dist/index.js doctor
```

There is no per-fixture runner; `test:detectors` iterates every file in `cases/detectors-project/`. Add a `safe-*.ts` (expected clean) or `unsafe-*.ts` fixture and register it in the expected-findings list inside `scripts/test-detectors.mjs`.

Run the CLI two ways: `node dist/index.js <cmd>` (compiled, what npm ships) or `node bin/safets.js <cmd>` (runs `src/` directly via ts-node — the dev path, no build needed).

## Import-extension gotcha

Source files import each other with explicit **`.ts`** specifiers (`import { analyze } from "./analyze.ts"`). This is intentional: `tsconfig.build.json` sets `rewriteRelativeImportExtensions`, which rewrites `.ts` -> `.js` during compilation. Keep using `.ts` in source imports — dropping the extension or using `.js` will break the build/runtime. `dist/` is gitignored but regenerated by the `prepare` script for publishing.

## Architecture

The pipeline is **load program → run detectors → report**. Entry point `src/index.ts` parses args, then:

- **JSON mode** (`--json`) runs analysis synchronously (`runAnalysisSync`).
- **Human mode** runs analysis in a **worker thread** (`src/analysis-worker.ts`) so a live progress timer/tips can render on the main thread. The worker re-runs the full load+analyze; results are serialized back (the `ts.Program` itself can't cross the thread boundary, so `programInputs` are recreated, not transferred).

### Program loading — `loadProgramRobust` (`src/analyze.ts`)

A resilience ladder, tried in order, recording `warnings[]` and a `strategy` tag at each fallback:

1. `root-tsconfig` — root `tsconfig.json`, validated via `isCheckerUsable` (a real `getSymbolsInScope` probe).
2. `workspace-tsconfigs` — discover nested `tsconfig.json` files; each becomes a `programInputs` slice analyzed separately in `analyze()`, with results de-duplicated. Files no tsconfig covers get scanned directly.
3. `direct-scan` — build one program from all discovered `.ts` files with default strict options.
4. `fallback` — AST-only, no type information. Only `detectFallbackPatterns` runs (JSON.parse + `process.env!`); everything else needs a `TypeChecker`.

Most `validate-real-world` targets never hit fallback. This whole subsystem is the hard part — changes here affect every detector's accuracy.

### Detectors — `src/detectors/index.ts`

Nine pattern detectors (`detectUnsafePropertyAccess`, `detectUnsafeDestructuring`, `detectUnsafeArrayAccess`, `detectUnsafeJsonParse`, `detectUnsafeEnvAccess`, `detectNonNullAssertionOnNullable`, `detectUnsafeAccessAfterAwait`, `detectUnsafePromiseAllDestructuring`, `detectUnsafeMapAccess`) plus the AST-only `detectFallbackPatterns`. Each walks the AST and returns `CrashReport[]`. All type-based detectors take `(sourceFile, checker)`; each is wrapped in try/catch in `analyzeProgram` so one bad file can't crash the run. Shared AST helpers (`isNullable`, `isOptionalAccess`, `getChainRoot`, `isInsideTryCatch`, etc.) live in `src/utils/ast.ts`. The canonical pattern list/confidence levels are in the README's "The 9 Patterns" table and `docs/guide/patterns.md`.

### Reporters — `src/reporters/`

- `index.ts` — human-readable `doctor`/`fix`/`debt` output.
- `json.ts` — machine output, versioned by `schemaVersion`. Keep it backward-compatible.
- `baseline.ts` — `.safets-baseline.json` read/write and the `isNew`/mismatch logic.

### Baseline system

`baseline` snapshots current crashes to `.safets-baseline.json` (committed by users). `doctor --fail-on-new` exits `1` only for crashes absent from the baseline. The baseline records its `options` (e.g. `includeTests`); `checkBaselineOptionsMismatch` **refuses** a `--fail-on-new` comparison when options differ rather than producing misleading results.

### File selection — `src/utils/files.ts`

Filtering rules live here: `SKIP_DIRS` (node_modules, dist, generated dirs, etc.), `TEST_PATTERNS` (excluded unless `--include-tests`), `.d.ts` excluded, and files over 5000 lines skipped as bundles/generated (`isBundleFile`). Only `.ts` files are analyzable (`isAnalyzableTsFile`).

## Conventions

- Pure ESM (`"type": "module"`), targets Node, strict TS with `noUncheckedIndexedAccess`.
- Exit codes: `0` success; `1` invalid CLI usage, incompatible `--fail-on-new` baseline, or new crashes found. Detectors must degrade gracefully (skip a file) rather than throw.
- Commands: `doctor` (default), `fix`, `debt`, `baseline`. Flags: `--include-tests`, `--baseline`, `--fail-on-new`, `--json`, `--help`, `--version`.
- When changing CLI behavior, flags, or JSON shape, update `README.md`, `docs/`, the `safets-agent` skill (`skills/safets-agent/SKILL.md`), and `action.yml` inputs together.

## CI

`.github/workflows/ci.yml` runs the quality suite on Node 24 across Ubuntu + Windows (path handling is cross-platform — use the `normalizeFilePath`/`toPortablePath` helpers), packs and installs the tarball in an isolated project, dogfoods the Action on this repo, and builds the VitePress docs (`docs/` is a separate npm project with its own lockfile).
